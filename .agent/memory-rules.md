# 🧠 Memory Rules for Development

> 이 규칙은 Claude가 대화 중 중요한 정보를 mem0에 자동 저장하도록 안내합니다.
> 목적: 토큰 절약, 백엔드/프론트엔드/CLI 간 컨텍스트 공유

---

## 📋 자동 저장 대상

### 1. 프로젝트 메타 정보

대화 초기 또는 변경 시 저장:

- 기술 스택 (프레임워크, 언어, 주요 라이브러리)
- 프로젝트 구조 (모노레포 여부, 폴더 구성)
- 배포 환경 (Vercel, AWS 등)
- API 엔드포인트 패턴

### 2. 코딩 스타일 & 선호도

사용자가 명시하거나 코드에서 패턴 발견 시:

- 들여쓰기 (탭/스페이스, 크기)
- 네이밍 컨벤션 (camelCase, snake_case 등)
- 파일 구조 선호 (컴포넌트당 폴더, 플랫 구조 등)
- 타입 정의 방식 (interface vs type)
- 상태관리 패턴 (Zustand, Redux, Context 등)

### 3. 진행 중인 작업

작업 시작/완료 시 업데이트:

- 현재 작업 중인 기능/이슈
- 연관된 파일/컴포넌트 목록
- 막혀있는 부분이나 TODO

### 4. 아키텍처 결정 (ADR)

중요한 결정 발생 시:

- 기술 선택 이유
- 컴포넌트 설계 방향
- API 설계 패턴
- 포기한 대안과 이유

### 5. 트러블슈팅 히스토리

문제 해결 시:

- 발생한 에러와 원인
- 해결 방법
- 재발 방지를 위한 주의사항

### 6. 외부 연동 정보

- 사용 중인 외부 API (키 제외!)
- 인증 방식
- 연동된 서비스들

---

## 🏷️ 저장 형식

mem0 저장 시 다음 패턴 사용:

```
[카테고리] 내용
예: [프로젝트] sto-link: Next.js 14 + TypeScript, App Router 사용
예: [스타일] TypeScript에서 interface 대신 type 선호
예: [진행중] CharacterGraph 컴포넌트 리팩토링 중
예: [결정] 상태관리는 Zustand 사용 - Redux는 보일러플레이트가 과함
예: [해결됨] hydration error - dynamic import로 클라이언트 컴포넌트 분리
```

---

## 🎯 저장 트리거

### 명시적 트리거 (사용자 키워드)

- "기억해", "저장해", "remember", "save"
- "이건 중요해", "나중에도 참고해"
- "항상 이렇게 해줘", "내 스타일은"

### 암묵적 트리거 (Claude 판단)

다음 상황에서 자동 저장 판단:

- 새 프로젝트 시작 또는 진입 시 → 프로젝트 정보
- 코딩 스타일 피드백 받았을 때 → 스타일 규칙
- 중요한 아키텍처 결정 했을 때 → ADR
- 오래 걸린 버그 해결했을 때 → 트러블슈팅
- 반복적으로 같은 설명을 하게 될 때 → 관련 컨텍스트

---

## 🔄 세션 시작 시

새 대화 시작 시 먼저 수행:

1. `recall` 함수로 현재 프로젝트 관련 기억 조회
2. 컨텍스트 로드 후 작업 시작
3. 사용자에게 "이전 작업 컨텍스트 로드했습니다" 알림 (간단히)

---

## ⚠️ 저장하지 않는 것

- API 키, 비밀번호, 토큰 등 민감 정보
- 일회성 디버깅 대화
- 단순 질문/답변
- 임시 테스트 코드

---

## 💡 활용 예시

### 토큰 절약

Before: 매번 "이 프로젝트는 Next.js 14 App Router 기반이고..."
After: 기억에서 자동 로드, 바로 작업 시작

### 컨텍스트 유지

- CLI에서 작업 → 에디터로 이동 → 같은 맥락 유지
- "아까 그 컴포넌트" → 기억에서 조회

### 일관성

- 코딩 스타일 규칙 저장 → 모든 코드 생성 시 적용
- 아키텍처 결정 저장 → 관련 작업 시 참조
