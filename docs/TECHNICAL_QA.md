## Part 1: 핵심 아키텍처 및 시스템 설계

### 1. 하이브리드 백엔드 및 인프라 아키텍처

**질문:** Spring Boot, FastAPI, MinIO 등 여러 서버를 사용하는 아키텍처의 의도와 구성은 무엇인가요?

**답변:**

- **Spring Boot (8080):** 서비스의 메인 두뇌입니다. 계정, 프로젝트, 문서 계층 구조, 복선 등 정규화된 데이터의 CRUD와 PostgreSQL/RDS 연동을 담당합니다.
- **FastAPI (8000):** 고성능 비동기 처리가 필요한 AI 채팅(`stolink-chat`) 및 스트리밍 서비스를 담당합니다. Python의 풍부한 LLM 생태계를 활용하기 위한 선택입니다.
- **MinIO (9001):** S3 호환 객체 스토리지를 로컬/개발 환경에서 제공합니다. 캐릭터 이미지, 도서 표지, 내보내기 파일 등 대용량 미디어 자산을 관리합니다.
- **Vite Proxy:** 개발 환경에서 `/api`, `/ai-api`, `/media` 경로를 각각의 서버로 라우팅하여 CORS 이슈 없이 통합된 개발 경험을 제공합니다.

### 2. D3 & Canvas 기반의 고성능 관계도 (4D Timeline)

**질문:** 라이브러리 대신 D3.js를 직접 사용한 이유와 특수 기능은 무엇인가요?

**답변:**

- **성능 및 커스터마이징:** 일반적인 라이브러리(React Flow 등)로는 구현하기 어려운 **100개 이상의 노드**에 대한 부드러운 Force Simulation과 Canvas 기반의 최적화된 렌더링을 위해 D3.js를 선택했습니다.
- **4D Timeline (Timeline Slider):** 소설의 현재 시점(챕터/장면)에 따라 관계가 점진적으로 드러나고 변화하는 '시간축 시각화' 기능을 제공합니다.
- **Universal Curvature:** 다중 관계 표현 시 간선이 겹치지 않도록 모든 엣지의 곡률을 동적으로 계산하며, BFS(Flow Depth) 탐색을 통해 주인공으로부터의 서사적 거리에 따른 애니메이션을 제어합니다.

### 3. SSE(Server-Sent Events)를 활용한 비동기 작업 추적

**질문:** 장시간 실행되는 분석 작업이나 이미지 생성 상태를 어떻게 실시간으로 관리하나요?

**답변:**

- **전역 상태 스트림:** `/api/project/:id/status/stream` 엔드포인트를 통해 프로젝트 내에서 발생하는 모든 AI 분석, 이미지 생성, 가져오기/내보내기 작업의 진행률(percent)과 결과를 실시간으로 수신합니다.
- **유연한 재연결:** SSE 연결이 끊기더라도 `useJobSSE` 훅과 `useAnalysisBufferStore`(IndexedDB)를 통해 마지막 Job ID를 추적하며, 복구 시 상태를 자동으로 동기화합니다.

### 4. 효율적인 AI 분석을 위한 콘텐츠 해싱

**질문:** AI 분석 요청을 최적화하는 구체적인 로직은 무엇인가요?

**답변:**

- **Selective Trigger:** 모든 문서 변경 시 분석을 돌리는 대신, 프론트엔드(`hashUtils.ts`)에서 문서 본문의 해시를 계산하여 `lastAnalyzedHashes`와 대조합니다.
- **Cost Saving:** 내용에 유의미한 변화가 있을 때만 `/api/ai/analyze` 요청을 보내고, 백엔드에서도 이 해시를 활용해 캐싱 처리함으로써 LLM API 호출 비용과 서버 부하를 최소화합니다.

### 5. Scrivenings 모드의 계층형 데이터 통합 편집

**질문:** 여러 문서를 하나로 합치는 '스크리브닝' 모드는 기술적으로 어떻게 구현되었나요?

**답변:**

- **Section Divider Architecture:** 개별 문서들을 Tiptap의 커스텀 노드인 `section-divider`로 구분하여 하나의 선형적인 문서로 병합해 렌더링합니다 (`ScriveningsEditor.tsx`).
- **Bulk Update:** 통합 뷰에서 편집이 발생하면 DOM 파싱을 통해 디바이더 사이의 텍스트를 추출하고, 변경된 문서들만 모아 `bulk-update` API로 원자적으로 전송하여 데이터 무결성을 유지합니다.

### 6. PostgreSQL과 Neo4j의 데이터 분산 저장 정책

**질문:** 두 데이터베이스 간에 데이터를 나누어 저장하는 기준과 정합성 유지 방식은 무엇인가요?

**답변:**

- **PostgreSQL (RDBMS):** 계정, 프로젝트 메타데이터, 복선 등 강력한 관계 정의와 트랜잭션이 필요한 정형 데이터를 저장합니다.
- **Neo4j (Graph DB):** 캐릭터 간의 복잡한 네트워크 관계, 장소, 아이템 간의 연결을 저장합니다.
- **정합성 관리:** 프론트엔드에서는 `Neo4j propagation safety`를 위해 작업 후 1초간의 지연 무효화(Invalidation) 처리를 수행하며 (`useCharacters.ts`), 백엔드에서 ID 기반의 강한 결합을 유지합니다.

### 7. AI 분석 "Stuck Mitigation" (방어적 UI 처리)

**질문:** 진행률 100% 도달 후 3초 강제 완료 처리가 필요한 이유는 무엇인가요?

**답변:**

- SSE 통신 시 서버의 작업 완료 시점과 클라이언트의 메시지 수신 시점 사이에 네트워크 지연이나 유실이 발생할 수 있습니다.
- 사용자 입장에서 '100%'에서 멈춰있는 현상을 방지하기 위해, 진행률이 최대치에 도달한 후 일정 시간 응답이 없으면 클라이언트가 선제적으로 완료 처리를 수행하고 최신 결과 데이터를 폴링하여 UX를 부드럽게 유지합니다.

### 8. Zustand와 TanStack Query의 상태 관리 원칙

**질문:** 프로젝트 내에서 두 라이브러리를 사용하는 명확한 기준은 무엇인가요?

**답변:**

- **TanStack Query (Server State):** 모든 API 데이터(문서, 캐릭터, 분석 결과)의 캐싱, 리패칭, 낙관적 업데이트를 담당합니다. 도메인별 `Keys` 팩토리 패턴을 사용합니다.
- **Zustand (UI/Local State):** 에디터 설정, 사이드바 개폐 여부, 줌 레벨 등 순수 클라이언트 UI 상태를 관리합니다.
- **Persistence:** 대용량 데이터인 '증분 분석 버퍼'는 `idb-keyval`을 통해 IndexedDB에 저장하여 브라우저 종료 시에도 유실되지 않도록 관리합니다.

### 9. ID 기반의 동적 캐릭터 멘션(Mentions) 연동

**질문:** 에디터 내의 `#캐릭터` 멘션 정보가 캐릭터 이름 변경 시 어떻게 자동 반영되나요?

**답변:**

- **Structure:** Tiptap의 `CharacterMention` 확장은 캐릭터 이름을 텍스트로 저장하지 않고, 캐릭터 고유의 `id`를 가진 커스텀 노드(`CharacterNodeView.tsx`)로 저장합니다.
- **Sync:** 에디터는 렌더링 시점에 Store에 있는 최신 캐릭터 정보를 ID로 조회하여 화면에 표시합니다. 따라서 사이드바에서 이름을 변경하면 에디터 내부의 모든 언급 지점이 즉시 업데이트됩니다.

### 10. 버전 관리 기반의 오프라인 편집 및 충돌 해결

**질문:** 오프라인 상황에서의 문서 편집 충돌을 어떻게 방지하나요?

**답변:**

- **Updated At Tracking:** 모든 리스폰스는 `updatedAt` 타임스탬프를 포함합니다.
- **S3 Snapshot:** 백엔드에서는 10분 주기로 문서 스냅샷을 S3에 보관하여 버전 복구를 지원합니다.
- **Conflict Strategy:** 오프라인 편집 후 온라인으로 복귀할 때, 타임스탬프 기반의 비교를 통해 서버 데이터와 충돌이 감지되면 사용자에게 공지하고 안전한 업데이트 경로를 제안합니다.

## Part 2: 심화 기술 상세 (Advanced Technical Deep-Dive)

### 11. Web Locks API를 이용한 탭 간 토큰 재발급 동기화

**질문:** 여러 브라우저 탭이 열려있을 때 401 에러가 동시에 발생하면 어떻게 중복 재발급 요청을 막나요?

**답변:**

- `navigator.locks.request`를 사용하여 "auth_refresh_lock"이라는 전역 락을 획득한 탭만 `/auth/refresh` 요청을 보냅니다.
- 나머지 탭들은 락이 해제될 때까지 대기하며, 해제 후 `last_refresh_time`을 확인하여 이미 갱신되었다면 중복 요청 없이 원래의 API만 재시도합니다 (`client.ts:83`).

### 12. 1000+ 노드 대응을 위한 CanvasGraph 최적화

**질문:** SVG 대신 `react-force-graph-2d` (Canvas)를 도입한 배경과 최적화 기법은 무엇인가요?

**답변:**

- **도입 배경:** 노드와 엣지가 100개를 넘어설 때 SVG 렌더링은 DOM 개수 폭증으로 성능이 급격히 저하됩니다. 픽셀 기반의 Canvas 렌더링을 통해 1000개 이상의 개체도 안정적인 60FPS를 유지합니다.
- **최적화:** `drawNode`, `drawLink`를 커스텀 구현하여 이미지를 캐싱(`useImageCache`)하고, `throttle`을 이용해 마우스 포지션 업데이트와 툴팁 렌더링 부하를 조절합니다 (`CanvasGraph/index.tsx`).

### 13. 집필 통계의 "Baseline" 기반 일일 집필량 산출 로직

**질문:** 단순히 총 글자수를 저장하지 않고 'Baseline' 방식을 사용하는 이유는 무엇인가요?

**답변:**

- `useWritingStatsStore.ts`는 하루의 첫 글쓰기 시점의 총 글자수를 `dailyBaselines`에 저장합니다.
- 이를 통해 **순수하게 오늘 작성한 글자수**(`currentTotalChars - baseline`)를 정확히 산출하며, 여러 기기에서 동기화되더라도 오늘 날짜의 기준점을 유지하여 스트릭(Streak) 계산의 정확도를 높입니다.

### 14. Neo4j ID 이중화 문제 해결 (Hotfix Mapping)

**질문:** `eventService.ts`에 존재하는 `CHARACTER_EVENT_ID_MAP` 하드코딩의 정체는 무엇인가요?

**답변:**

- Neo4j 노드 생성 시 `characterId`와 내부 `id`가 공존하거나 레거시 데이터와의 불일치가 발생하는 엣지 케이스를 해결하기 위한 임시 매핑 테이블입니다. (`HOTFIX: characterId → id 매핑`)
- 이는 특정 캐릭터의 이벤트를 조회할 때 발생할 수 있는 데이터 누락을 방지하는 방어적 코드입니다.

### 15. Tiptap 커스텀 노드뷰와 React 컴포넌트 브릿지

**질문:** 에디터 내부의 `#복선` 태그가 단순 텍스트가 아닌 인터랙티브한 UI로 동작하는 원리는 무엇인가요?

**답변:**

- `ReactNodeViewRenderer`를 사용하여 Tiptap의 ProseMirror 노드 안에 실제 React 컴포넌트를 주입합니다.
- 이를 통해 에디터 내에서 복선 상태를 직접 토글하거나, 클릭 시 사이드바의 상세 정보로 연결되는 리치한 UI 경험을 제공합니다.

### 16. @stolink/ui 및 @stolink/tokens 디자인 시스템 구조

**질문:** 프로젝트 내부 모노레포 구조에서 디자인 토큰은 어떻게 관리되나요?

**답변:**

- `package.json`의 `workspaces`를 통해 `@stolink/tokens`(색상, 타이포 필드)와 `@stolink/ui`(공통 컴포넌트)를 별도 패키지로 관리합니다.
- `npm run build:packages`를 통해 토큰을 먼저 빌드하여 메인 앱의 Tailwind 설정에 주입함으로써, 일관된 디자인 시스템(Mocha & Cloud Dancer)을 유지합니다.

### 17. IndexedDB를 활용한 대용량 증분 분석 버퍼 관리

**질문:** `localStorage` 대신 `idb-keyval`을 사용하여 분석 버퍼를 저장하는 이유는 무엇인가요?

**답변:**

- 장편 소설의 경우 전체 내용이 수십 MB를 넘을 수 있어 `localStorage`(5MB 제한)로는 부족합니다.
- 비동기 키-값 저장소인 IndexedDB를 활용하여 대용량 텍스트 버퍼를 안전하게 저장하고, 브라우저가 예기치 않게 종료되어도 작성 중인 분석 데이터를 보존합니다.

### 18. Export 작업의 비동기 폴링(Cycle) 프로세스

**질문:** 사용자가 내보내기 버튼을 눌렀을 때의 전체 워크플로우는 어떻게 되나요?

**답변:**

- 1. `useExportProject` 호출 -> 백엔드에 Job 생성 및 `jobId` 수신.
- 2. `useExportStatus`가 2초 간격으로 폴링 수행.
- 3. 작업 완료(`completed`) 시 반환된 `downloadUrl`을 통해 파일을 다운로드하고 임시 Job 데이터를 정리합니다.

### 19. 다중 관계 시각화를 위한 Curvature & Super Edge 로직

**질문:** 두 캐릭터 사이에 관계가 여러 개일 때(예: 친구이면서 라이벌) 그래프에서 어떻게 표현하나요?

**답변:**

- `processedLinks` 가공 시 동일한 소스-타겟 쌍을 `pairMap`으로 그룹화합니다.
- 관계가 2개 이상이거나 복합적인 경우 `isSuperEdge` 속성을 부여하고, 관계 유형 우선순위(`RELATION_PRIORITY`)에 따라 대표 색상을 결정하거나 곡률을 강제로 분산하여 시각적 중첩을 방지합니다.

### 20. 에러 바운더리와 레이어별 예외 처리 전략

**질문:** API 호출 실패나 에디터 렌더링 에러가 앱 전체의 중단으로 이어지지 않게 하는 방법은 무엇인가요?

**답변:**

- **Service Layer:** `eventService.ts`와 같이 개별 서비스에서 `try-catch`와 `console.warn`을 통해 404 등 예상 가능한 에러를 swallow하고 빈 배열을 반환하여 UI가 깨지지 않게 합니다.
- **Global Boundary:** React 19의 Error Boundary를 주요 페이지 레이아웃(`App.tsx`)에 배치하여, 치명적 에러 시 폴백 UI(에러 안내 페이지)를 보여주고 상태 초기화를 유도합니다.
