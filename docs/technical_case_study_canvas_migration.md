# [Technical Case Study] 1000+ 노드 렌더링을 위한 캔버스 마이그레이션과 스타일 재계산 최적화

## 1. Context & Problem (문제 정의)

### 상황 (Context)

StoLink 프로젝트는 작가가 복잡한 캐릭터 관계도를 시각적으로 관리하는 도구입니다. 대하소설 급의 세계관을 지원하면서 노드와 간선의 개수가 급증함에 따라 기존 SVG 기반 렌더링 엔진에서 심각한 한계에 부딪혔습니다.

### 문제 (Problem)

기존 SVG/DOM 기반 렌더링 환경에서 노드가 약 30개 이상으로 늘어날 때 브라우저 렌더링 파이프라인의 임계치를 초과했습니다.

- **현상**: 화면 줌/팬(Zoom/Pan) 조작 시 FPS가 10 미만으로 하락하며, 드래그 시 입력 지연 발생.
- **프로파일링 데이터 (Before)**:
  - **Style Recalculation**: 프레임당 **935ms** 소요 (요소 28개 대상)
  - **INP (Interaction to Next Paint)**: **1,048ms** (매우 나쁨)
  - **LCP (Largest Contentful Paint)**: **2.30s**

> **진단**: DOM 요소가 많아질수록 기하급수적으로 늘어나는 스타일 재계산(Style Recalculation) 비용이 메인 스레드를 점유하여 인터랙션 마비를 유발함.

---

## 2. Root Cause Analysis (원인 분석)

1.  **Layout Thrashing & Style Recalculation**:
    - Force Simulation의 특성상 매 틱(tick)마다 모든 노드와 간선의 위치 속성(transform)이 변경됩니다.
    - 수백 개의 DOM 요소에 대해 매 프레임마다 스타일 계산과 레이아웃 연산이 반복되면서 브라우저가 과부하 상태에 빠졌습니다. (Image 3 - Style Recalculation 935ms 참조)

2.  **DOM Overhead**:
    - 브라우저의 렌더 트리 구성 및 레이어 합성 오버헤드가 노드 수에 비례하여 증가했습니다.

---

## 3. Solution Discovery & Trade-offs (대안 탐색)

| 대안                       | 설명                                            | 장단점 및 판정                                                                   |
| :------------------------- | :---------------------------------------------- | :------------------------------------------------------------------------------- |
| **A. DOM 최적화**          | CSS `content-visibility`, `will-change` 등 사용 | 연결된 그래프 구조상 모든 노드가 영향을 받아 효과가 제한적임 (기각)              |
| **B. SVG 가상화**          | Viewport 밖 요소 렌더링 제외                    | 전체 보기 모드에서 모든 노드를 그려야 하므로 해결책이 되지 않음 (기각)           |
| **C. Canvas 마이그레이션** | **HTML5 Canvas**를 이용한 통합 픽셀 렌더링      | **압도적인 렌더링 성능**을 제공하나, 상호작용 로직을 직접 구현해야 함 (**채택**) |

---

## 4. Architectural Decision (ADR)

**Decision**: 그래프 렌더링 엔진을 SVG(DOM)에서 **Canvas API (`react-force-graph-2d`)**로 전면 전환한다.

**Rationale**:

- Canvas는 수천 개의 객체를 단일 레이어에서 비트맵으로 렌더링하므로 브라우저의 스타일 재계산 부하를 '0'으로 만듭니다.
- LOD(Level of Detail) 렌더링과 이미지 캐싱을 통해 600+ 노드 환경에서도 60 FPS 부드러운 사용자 경험을 보장할 수 있습니다.

---

## 5. Implementation & Optimization (구현 요점)

1.  **Single Layer Integration**: 개별 노드를 DOM으로 관리하던 방식에서 벗어나, Canvas 컨텍스트 내에서 모든 드로잉을 일괄 처리(Batch Drawing)하도록 구현했습니다.
2.  **Image Caching**: `useImageCache`를 도입하여 캐릭터 초상화를 텍스처로 메모리에 상주시켜 드로잉 성능을 최적화했습니다.
3.  **Super Edge Integration**: 복합 관계를 "Braided(새끼줄)" 패턴으로 시각화하여 데이터의 복잡도는 유지하면서 렌더링 요소는 최적화했습니다.
4.  **Directional Cues**: 양방향(Bidirectional) 관계에 대해 중앙에서 뻗어나가는 Pulse 애니메이션과 이중 화살표를 적용하여 직관성을 높였습니다.

---

## 6. Quantitative Impact (성과 지표)

마이그레이션 후 실제 크롬 성능 측정 결과, 모든 지표에서 극적인 개선을 확인했습니다. (이미지 1 참조)

| 지표                    | 마이그레이션 전 (SVG) | 마이그레이션 후 (Canvas) | 개선율          |
| :---------------------- | :-------------------- | :----------------------- | :-------------- |
| **Style Recalculation** | **935ms**             | **~0ms**                 | **100% 제거**   |
| **INP (응답 속도)**     | **1,048ms** (Bad)     | **64ms** (Good)          | **16.3배 향상** |
| **LCP (초기 로드)**     | **2.30s**             | **0.58s**                | **4배 향상**    |
| **Rendering FPS**       | 5~10 FPS              | **60 FPS** (Stable)      | **6배 향상**    |

### 2026-01-20 추가 벤치마크 (소규모 vs 대규모 데이터 비교)

최신 개발 환경에서 v2.0(Legacy SVG)와 v3.0(Canvas)의 성능을 직접 비교 측정한 결과입니다.

| 항목               | v2.0 SVG (Legacy) | v3.0 Canvas (Modern) | 데이터 규모 차이 |
| :----------------- | :---------------- | :------------------- | :--------------- |
| **테스트 노드 수** | 28개 (소규모)     | **600개** (대규모)   | **21배 증가**    |
| **평균 FPS**       | 29 FPS (불안정)   | **57 FPS** (쾌적)    | **~2배 향상**    |
| **1% Low FPS**     | 19 FPS            | 29 FPS               | 스터터링 감소    |
| **메모리 사용**    | 105 MB            | **94 MB**            | **11MB 절감**    |

> **Insight**: Legacy SVG 엔진은 불과 28개의 노드에서도 30 FPS 방어가 어려웠으나, Canvas 엔진은 그 21배에 달하는 600개 노드를 처리하면서도 2배 가까운 프레임레이트를 확보했습니다. 또한 DOM 요소를 제거함으로써 대규모 데이터임에도 메모리 사용량이 오히려 감소하는 효율성을 입증했습니다.

---

## 결론

이번 마이그레이션을 통해 StoLink는 수천 명의 캐릭터가 얽힌 대규모 장편 소설의 복선과 인간관계를 작가가 아무런 지연 없이 실시간으로 탐색할 수 있는 고성능 툴로 진화했습니다. 이는 단순히 기술적 전환을 넘어 사용자의 '창작 경험'을 극대화한 핵심 최적화 사례입니다.
